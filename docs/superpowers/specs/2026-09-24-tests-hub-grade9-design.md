# Самостійні роботи: загальна сторінка й тести для 9 класу — дизайн-документ

Дата: 2026-09-24
Статус: чернетка, чекає на перегляд
Гілка: `feature/tests-hub-grade9`

## 1. Мета

Сайт має одну самостійну роботу — «Перевір себе» (`#/check`), яку вже пройшла
Старша інженерна школа. Потрібно:

1. Загальна сторінка **«Самостійні роботи»** (`#/tests`) з двома розділами —
   **Старша інженерна школа** (туди переїжджає наявний тест) і **9 клас**.
2. **Тест для 9 класу** (`#/check-9`) — такий самий формат, максимум 12 балів,
   трохи більше питань і практики, лише пройдені теми.
3. **Розширений варіант для 9 класу** (`#/check-9plus`) — для учня, який уже
   вчив Python (курс з іграми на кшталт Breakout): менше простого, більше
   циклів і списків. Теж 12 балів. Доступний лише за прямим посиланням.

Критерій успіху: учні 9 класу проходять тест у браузері без встановлення
Python, отримують бал і посилання на результат для вчителя; інженерна школа
не помічає змін — старі результати й посилання працюють.

## 2. Межі

**Робимо:** спільний рушій самостійних робіт, новий тип завдання «програма»
(`input()` → `print()`), сторінку `#/tests`, два нові тести, правки меню й
головної.

**Не робимо:** змін у завданнях інженерного тесту; сервера чи облікових
записів (усе, як і раніше, у localStorage + посилання); показу статусу
«пройдено» на картках сторінки `#/tests`; збірки — сайт лишається статичним.

## 3. Вихідний стан

- `js/pages/check.js` (~1200 рядків) — усе разом: пул `SLOTS`, вибір
  варіантів (`makePick`), чернетка, Python-обв'язка для типу `code`
  (функція + приховані тести), оцінювання, посилання `#/check/r/<дані>`,
  рендер результатів.
- Розмітка сторінки тесту захардкоджена в `index.html` (`#page-check`),
  зокрема текст «Відповіли 0 з 9».
- `js/app.js` — `ROUTES` з підпунктами `kids`, плаский `FLAT` для меню й
  кнопок «далі / назад»; роутер дивиться лише на перший сегмент хеша.
- `js/pyeditor.js` — редактор з підсвіткою, автодоповненням і
  `bootPyodide()`; спільний для практики й тесту.

## 4. Що пройшов 9 клас (джерело — `IT_9/Lessons`, Lesson1–3)

**Можна в базовий тест:** `print`, `input`, змінні, `int()`, `str()`,
склеювання рядків `+` і множення рядка на число, f-рядки, арифметика й
порядок дій, порівняння `== != < > <= >=`, `True/False`, `=` проти `==`,
`'5' == 5`, `if / elif / else`, відступи, вкладені `if`, `and` / `or`,
`random.randint`, `random.choice`, `for` + `range(n)` / `range(a, b)` /
`range(a, b, крок)`, лічильник і накопичувач у циклі.

**Не можна в базовий тест:** `while`, `break`, `def`, методи списків,
індекси списків (списки траплялись лише як літерал у `random.choice`).

**Розширений варіант** додатково: `while`, `break`, списки (створення,
індекси включно з `-1`, `append`, `len`, `in`, прохід циклом). Акцент — на
вмінні працювати з конструкціями, а не на вбудованих `sum`/`min`/`max`:
задачі розв'язуються циклом і умовами, вбудовані функції не заборонені, але
нічого не дають. `def` не використовуємо.

## 5. Навігація й адреси

**Бічне меню:** пункт «✓ Перевір себе» стає «✓ **Самостійні роботи**»
(`#/tests`) з підпунктами:
- «Інженерна школа: Перевір себе» → `#/check`
- «9 клас: Самостійна робота» → `#/check-9`

`#/check-9plus` — маршрут із прапорцем `hidden`: він існує й відкривається,
але його немає в меню, на `#/tests` і в кнопках «далі / назад». У меню при
відкритому прихованому маршруті підсвічується «Самостійні роботи».

**Сторінка `#/tests`** — статична розмітка в `index.html`: заголовок, два
розділи з картками (стиль як у наявної картки `.card.check`). Окремий JS не
потрібен.

**Головна:** розділ «Перевір себе» лишається, картка веде на `#/tests` і
описує обидва класи.

| Тест | Адреса | Посилання на результат | Ключі localStorage |
|---|---|---|---|
| Інженерна | `#/check` | `#/check/r/…` (як було) | `pyguide_check_pick/_draft/_result` (як було) |
| 9 клас | `#/check-9` | `#/check-9/r/…` | `pyguide_check9_*` |
| 9 клас, розширений | `#/check-9plus` | `#/check-9plus/r/…` | `pyguide_check9plus_*` |

Кожен тест має власну «одну спробу» — результат одного не блокує інший.

## 6. Структура коду

```
js/checks/engine.js               рушій (window.CheckEngine)
js/checks/engineering/check.js    дані інженерного тесту (SLOTS як є)
js/checks/grade9/base.js          дані тесту 9 класу
js/checks/grade9/plus.js          дані розширеного варіанту
```

`js/pages/check.js` видаляється — його логіка переїжджає в `engine.js`,
а `SLOTS` — у `engineering/check.js` **без змін у текстах і стартовому коді**
(від стартового коду залежать старі посилання, див. §8).

Кожен файл даних реєструє тест:

```js
CheckEngine.define({
  slug: "check-9",               // маршрут і префікс посилання
  storage: "pyguide_check9",     // префікс ключів localStorage
  title: "Самостійна робота — 9 клас",
  lede: "…",                     // HTML під заголовком
  rules: "…",                    // HTML блоку «Одна спроба…»
  acHidden: { slotId: Set },     // слова, прибрані з автодоповнення
  slots: [ … ]
});
```

`define` реєструє `window.PageInit[slug]`, який при першому відкритті
будує вміст сторінки. У `index.html` три секції тестів — однакові порожні
контейнери `<section class="page" id="page-<slug>"><div class="wrap wide"></div></section>`;
заголовок, правила, прогрес («Відповіли 0 з N» з реальним N), слоти,
кнопку «Завершити» й блок результатів малює рушій.

Рушій зберігає поведінку наявного тесту: випадковий варіант і порядок
відповідей при першому візиті, чернетка, подвійне натискання «Завершити»,
результат назавжди в браузері, режим перегляду чужого результату за
посиланням, повідомлення про пошкоджене чи застаріле посилання. Уся
внутрішня логіка стає замиканням над конфігом тесту — ніяких спільних
глобальних станів між тестами. Pyodide завантажується один раз і ділиться
між усіма тестами (`PyEditor.bootPyodide()` уже кешує).

`app.js`: `ROUTES` отримує вузол `tests` з `kids` (`check`, `check-9`,
`check-9plus` з `hidden:true`); меню й `FLAT` для «далі / назад»
пропускають `hidden`. `ALIAS` не потрібен — `#/check` лишається дійсним
маршрутом.

## 7. Типи завдань

- **`mcq`** — як зараз: 1 бал; `credit` 1 / 0.5 (правильна логіка, синтаксична
  помилка) / 0.
- **`code`** — як зараз (функція + приховані тести на повернене значення).
  Використовує лише інженерний тест.
- **`program`** — нове, для 9 класу.

### 7.1. Завдання «програма»

Поля варіанта:

```js
{ title, intro, hint,
  starter,          // короткий коментар-підказка (+ за потреби готові рядки)
  sample: "5\n3",   // вхідні дані для кнопки «Запустити» за замовчуванням
  tests: [ { input:"5\n3", output:"8" }, … ],   // 4–6 прихованих наборів
  solution }
```

**Інтерфейс:** умова з прикладом «ввели → має вивести», редактор, поле
**«Вхідні дані для запуску»** (по значенню на рядок, заповнене `sample`),
кнопка «▶ Запустити» → блок з виводом програми або помилкою. Вердикт
«правильно/ні» до завершення тесту не показується. Вміст поля вхідних даних
зберігається в чернетці для зручності, у посилання не йде.

**Запуск (Python-обв'язка, `prog_run(source, input_text, max_steps)`):**
- кожен запуск — свіжий простір імен, `exec(compile(source, "main.py", "exec"))`;
- `input(prompt="")` бере наступний рядок із `input_text`; підказка `prompt`
  у вивід **не** потрапляє; якщо рядки скінчились — помилка
  «Програма просить більше даних, ніж передбачено умовою»;
- `print` пишеться в буфер через `redirect_stdout`;
- `sys.settrace` рахує рядкові події; понад `max_steps` (100 000) — зупинка з
  повідомленням «Схоже, цикл ніколи не закінчується»;
- повертає JSON `{out, error}`; `error` — `ТипПомилки: текст` або одне з
  повідомлень вище.

**Порівняння виводу:** рядки з `rstrip()`, порожні рядки в кінці
відкидаються, решта — точний збіг. Тому в умові завжди явно написано, що
саме вивести («виведи лише число», «виведи рядок `Рахунок: 5`»).

**Оцінка:** бал лише якщо пройдено всі набори. `random` у завданнях
«програма» не використовується.

**Результати:** пройдено / ні, код учня, приклад розв'язку; якщо ні — перший
набір, на якому програма помилилась: «ввели → очікувалось → твоя програма
вивела» (або помилка).

## 8. Посилання на результат

Формат лишається: `[версія, час, контрольна сума стартових кодів, пункти…]`,
стиснення deflate-raw + base64url, префікс `z`/`j`.

- Регулярний вираз посилання будується з `slug`: `^#/?<slug>/r/(…)$`.
  Для `check` він збігається з нинішнім.
- Пункт `mcq` — `[варіант, відповідь | -1]` (як було).
- Пункт `code` — `[варіант, 1/0, різниця з початковим кодом, помилка]` (як було).
- Пункт `program` — `[варіант, 1/0, різниця з початковим кодом, помилка, індекс першого проваленого набору | -1, фактичний вивід на ньому (обрізаний до 500 символів)]`.
  Так результат за посиланням показує діагностику без повторного запуску Python.
- Контрольна сума охоплює стартовий код пунктів `code` і `program`.
- Версія формату для інженерного тесту лишається `2` — байт-у-байт той самий
  payload, тому старі посилання відкриваються. Нові тести стартують з версії `1`.

Як і раніше, стартовий код уже виданих варіантів не можна змінювати
(нове — новим варіантом у кінець списку).

### 9.2. 9 клас — розширений (`#/check-9plus`): 9 завдань, 12 балів

Тематика Breakout (м'яч, платформа, цеглини, очки). Практика проста за
логікою — перевіряє вміння працювати з конструкцією, а не алгоритмічну
кмітливість.

| № | Тип | Тема | Бали |
|---|---|---|---|
| 1 | mcq | база: `print` / `input` / `int`, f-рядки | 1 |
| 2 | mcq | база: `if / elif / else`, `and` / `or` | 1 |
| 3 | mcq | `for` / `range`, накопичувач («що виведе?») | 1 |
| 4 | mcq | `while` і `break` (скільки разів виконається, де нескінченний цикл) | 1 |
| 5 | mcq | списки: індекси (зокрема `-1`), `append`, `len`, `in` | 1 |
| 6 | program | `for`: ввести N, потім N чисел (очки за цеглини) — вивести загальний рахунок | 2 |
| 7 | program | `while`: м'яч падає з висоти H з кроком S — вивести, за скільки кадрів торкнеться землі | 2 |
| 8 | program | список + цикл: ввести кілька значень у список, вивести, скільки з них відповідають умові (напр. червоні цеглини) | 2 |
| 9 | program | список: додати введене значення в готовий список і вивести `len` та останній елемент | 1 |

Точні тексти всіх варіантів, приховані набори й розв'язки пишуться під час
реалізації у `grade9/*.js` — вчитель переглядає їх перед злиттям гілки.

## 10. Перевірка

Тестового фреймворку в проєкті немає — перевіряємо так:

1. **Самоперевірка пулів** — `CheckEngine.selfTest(slug)` (викликається з
   консолі браузера): для кожного варіанта кожного `code`/`program`
   розв'язок проходить усі приховані набори, стартовий код — ні; кожне `mcq`
   має рівно один варіант з `credit:1`. Запускаємо для всіх трьох тестів.
2. **Сумісність інженерного тесту** — на `main` проходимо тест і зберігаємо
   посилання; на гілці воно відкривається з тим самим балом і відповідями.
   Наявний результат у localStorage (`pyguide_check_result`) показується без
   змін.
3. **Ручний прохід у браузері** для `#/check-9` і `#/check-9plus`: відповіді,
   «Запустити» з різними вхідними даними, нескінченний цикл, завершення,
   посилання, відкриття посилання в іншому браузері/вкладці-інкогніто.
4. **Навігація:** меню, `#/tests`, головна, «далі / назад», прихованість
   `#/check-9plus`, мобільна ширина.
